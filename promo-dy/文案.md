## 正文

兄弟们，WorkBuddy 国内版反代是不是都用不了了。

每轮对话第一步就挂，回一句：

```
400: workbuddy upstream client (http 400): 请求被拦截，请重新发送
code: 11128
```

换账号、换模型、换机器、换网络，全试过，一点用没有。

因为问题根本不在你这头。

我把 system prompt 一段一段截短去试，测出来一个特别离谱的事：截到 25860 个字符是 200，截到 25865 就是 400。差 5 个字符，正好跨过去一个 @。

国内网关会扫 system 消息，看到 @ 就判成非授权渠道调用，直接回 11128。你压根不知道自己哪里"非授权"，因为那是个普通符号。

我写了个 DSH 插件，在请求发出去之前把 system 里的 @ 换成 (at)，语义一个字没动，网关看着就是个普通字符。国际版不拦，所以插件默认只管国内那条路。

不碰你的内核和配置，不改你的账号密钥，不动额度不绕收费。钩在 fetch 层，网关哪天把这规则撤了，插件自己就失效，不用卸载。

装就一行：`node install.mjs`

零运行时依赖，MIT，代码可以直接看。

👉 github.com/curo22/dsh-wb400-guard
